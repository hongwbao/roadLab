## 原始 oracle 与浏览器适配

数值证据分为四类，不能互相替代：

1. 原 DLL 方法直接执行，记录程序集 SHA/MVID、方法身份、输入输出。
2. 自动从恢复 C# 提取的方法体，只有查询/容器/宿主边界替换；记录提取体 SHA 和替换范围。
3. 浏览器几何和数据适配器的场景、不变量与集成测试。
4. 完整原游戏运行时的交通轨迹。本轮提供物中没有该环境，尚无此级证据。

原 DLL / 源提取 oracle 均在本地分析工作区保留可重建工程。仓库 fixture 仅包含输入、输出与身份记录。源码不是通过把同一份 TypeScript 再运行一遍而自证。

已经发现并保留的跨语言边界包括：Unity `0/0` 流速饱和结果为 1；`RoundToInt` 的偶数舍入；信号桥梁移动时间必须逐步 float32，避免提前换态；控制器输入速度需要先转 float32，避免无冲突时因微小差值生成虚假停止点。

## 当前浏览器语义

- 默认模型标记为 `cs2-derived`，表示源逻辑加明确记录的浏览器适配，不是已经证明全行为相同。
- `legacy` 是原 IDM/MOBIL/预测让行对照路径，可在内部 API 的 `Simulation.trafficModel` 上选择并重新 configure。少数原模型专用数值测试明确标为 legacy；车身分离、路由可达、目标出口容量等通用不变量继续检查新模型。
- 新模型使用 60Hz 固定时钟，每车导航和向量移动按 16 组更新，阻塞检测采用对应分频；普通新车使用源的最少在场数量组分配与首索引平局规则。完整世界其他实体的组负载和 prefab/controller 组仍需宿主信息。
- 边界测试车映射为源的 `DummyTraffic` 角色。真正的 Stuck 链触发后，原 `PersonalCarAISystem.ParkCar` 会删除此类失败车。浏览器记录 `failed`，不增加 `completed`；正常红灯/拥堵排队本身不构成失败。
- 已有存档的 protected/sequential 保留手工配时。新添加的灯默认使用源分组与需求选择的自动感应模式。
- 源引擎现在实际通过普通车速度迭代器处理 LaneObjects、重叠窗和预约；旧全局车身截停不能与正常限速、转弯和跟车减速混称。最终组合的无重叠、低流量通行与高压力行为仍须验证。
- `Simulation` 已接到 `Cs2TrafficSimulation`，浏览器默认采用 Worker，Node 同步测试使用同一搜索内核并保留车辆结果下一帧交付边界。暂停时的可达性诊断独立返回，避免界面无法开始；运行中需求修改不重置车与时钟。
