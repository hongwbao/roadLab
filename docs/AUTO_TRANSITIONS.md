# 道路接头手动启用的平滑过渡

当前升级工具还支持隔离带宽度（含有／无隔离带）、等车道数横向偏移和非对称断面衔接；点击任一相邻路段可启用，右键取消。不同断面的接头由局部车道和实体宽度共同计算，具体操作见 [道路升级与右键操作](ROAD_UPGRADES.md)。

新建道路和单侧扩宽默认直接连接，保留端点的完整车道。需要渐变时，在“升级”中选择“添加平滑过渡”，点击相接的任一路段；两车道接三车道时在三车道一侧平滑展开，同车道数则协商隔离带宽度和横向位置。选择“恢复直接连接”移除渐变。空余车道可以直接接入其他普通道路，详见 [单侧扩宽与手动过渡](ROAD_EXPANSION.md)。

道路仍保留选择时的名义车道数和原有控制点，不增加一段需要玩家维护的道路。路面、边线、虚线和车辆轨迹共同使用同一套有效断面。指定车道组的接头保留车道对应关系；左侧、右侧或中间的保留车道可与既有车道精确衔接。双向道路按各自方向的数量分别处理，支持非对称断面。

## 启用后的接头判定

- 只处理方向连续、同高度、单一延续的道路接头。道路单向／双向属性须一致，端点切线需接近连续。
- 车道数量可包含时在较多一侧生成过渡；同数量按隔离带宽度或横向偏移决定。3＋2与2＋3通过共同2＋2接头衔接。
- 多臂路口和分合流不自动丢弃通行车道；单一延续的匝道接头可以参与过渡。已有显式渐变断面和切分后的渐变 profile 继续使用原有形状。
- 根据速度、车道差、隔离带宽差、横向偏移和可用路长选择过渡长度。单端最多使用该道路 80% 的长度，两端同时需要过渡时各最多使用 42%，保留中间断面。
- 断开、删除或替换相邻道路后重新推导过渡。保存、重载和撤销后使用相同规则恢复。

车道宽度差大于 0.2 米的接口不自动处理；较小宽度差仍使用各资产的原始车道宽度，通过原有短连接衔接。过渡长度是原型参数，极短路段需要玩家延长。

## 实现接口

`src/core/auto-transitions.ts` 提供两个独立函数：

```ts
updateAutomaticTransitions(project: Project): void;
automaticTransitionPreview(project: Project, incoming: Road[]): {
  roads: Road[];
  replaces: string[];
  hasTransitions: boolean;
};
```

`updateAutomaticTransitions` 在相接路段至少一侧 `Road.transitionMode === "smooth"` 时协商局部断面，并原地更新派生字段 `Road.autoTaper`，不会修改道路 ID、名义车道数、控制点、车道转向规则、车道接口或路网通行口。端点候选使用空间单元筛选；重复运行得到相同结果。

`automaticTransitionPreview` 对道路副本计算预览，返回新增及受影响的道路，以及需替代显示的原道路 ID。原地图和输入道路不被修改。新建道路的鼠标预览直接显示完整断面，不为相邻道路自动生成过渡。

派生字段包含起点／终点的有效车道数、保留车道组起始索引、横向偏移、端点隔离带宽度（`medianWidth`，可为零）和局部曲线参数范围。`src/core/math.ts` 中 `baseCountAt` 读取名义断面，`countAt`、`laneWidth`、`lanePoint`、`boundaryPoint` 和 `center` 读取有效断面。路面与模拟无需各自实现另一套过渡逻辑。

导入时校验派生字段；道路编辑及模拟 configure 时重新生成。普通道路内部自动分段后，先清除复制的派生字段，再依据实际相邻路段重新推导；不要把一次自动过渡改写成显式 `lanesStart/lanesEnd` 渐变资产。

## 验证

`tests/auto-transitions.test.ts` 覆盖普通 2→3、3→2、不同保留车道组、双向道路、双端短路段、断开恢复、路口／分流排除、存档、连续路面边缘、有／无及不同宽度的隔离带、等车道数横向偏移、交错非对称断面、预览不修改地图，以及真实车流通过而不发生车身重叠。

`tests/browser/auto-transitions.spec.ts` 使用普通道路资产和真实鼠标验证默认直接建造、手动升级、保存重载、删除恢复、撤销、双向道路和窄屏布局。

自动过渡不改动红绿灯、局部预测让行或其他驾驶策略。

## 车道连线与过渡标线

`src/core/transition-markings.ts` 的 `transitionMarkings(project, connections, physicalJunctions)` 消费 `connections(project)` 的最终合法映射（包括 `junctionLaneConnections`），返回按道路和车道边界索引组织的端点局部标线计划。`separatorPaths(road, index, range, plan)` 输出沿真实 `boundaryPoint` 的路径；不会修改 `lanePoint`、控制点、过渡设置或交通路线。J工具的虚拟端口 inset 不属于物理车道几何，不用作标线起终点。

只有独占、相邻且横向保序的车道分区，且两侧实际车道中心与分界在接缝各相差小于0.1m时，分隔线才连续。多出、多入、交叉、关闭的有效车道、非对齐横向跳接无法支持分隔线时，在该端实际平滑领口内留白；没有派生领口的平滑接头使用最多24m、单端不超过42%路长的局部范围。物理消失的车道仍按实际宽度收线，不虚构出口。所有保留采样点严格等于真实边界点；不会取两端中点把分隔线挪到实际行驶轨迹上。

合法映射变化可保留几何匹配的边界并撤去关闭邻车道的边界。对于同宽三车道的0→1、1→2横向跳接，即使两条连接本身保序，普通接头没有真实纵向连接段，也不能绘制移位边界，因此局部留白。真实交叉路口继续用 `roadRange` 裁掉普通标线，保留既有斑马线；中央隔离带和双向中心分界仅依物理几何。直接模式不因连线编辑开启平滑，右键取消后不残留局部标线计划。

渲染签名包含最终车道规则，但每条道路只依赖自己的局部计划；无关道路继续复用缓存路面。建造/替换预览只对附近道路计算接缝计划，不在鼠标移动时重新路由整张路网。虚线材质维持世界距离3m实线/6m间隔，不按道路长度缩放。

`tests/transition-markings.test.ts` 覆盖17项几何/映射反例及预览弧长分布；`tests/browser/road-construction-all-nodes.spec.ts` 验证真实连线消费、局部缓存失效、撤销/重载、右键取消、直接模式、清理与双向按车道吸附落地。
