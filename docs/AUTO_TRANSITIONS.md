# 道路接头自动车道过渡

选择普通道路资产直接连接即可。例如先建两车道单行道，再接三车道单行道，三车道路段靠近接头的一小段会自动从两车道平滑展开；反过来连接，则在三车道一侧提前平滑收窄。无需先放置一段专用过渡资产。

道路仍保留选择时的名义车道数和原有控制点，不增加一段需要玩家维护的道路。路面、边线、虚线和车辆轨迹共同使用同一套有效断面。指定车道组的接头保留车道对应关系；左侧、右侧或中间的保留车道可与既有车道精确衔接。双向道路在两个方向同步处理。

## 自动判定

- 只处理方向连续、同高度、单一延续的道路接头。道路单向／双向属性须一致，端点切线需接近连续。
- 过渡生成在车道较多的一侧，较窄道路的断面和控制点保持原样。
- 路口、分合流以及匝道接口不自动丢弃主线车道。已有显式渐变断面和切分后的渐变 profile 继续使用原有形状。
- 根据速度、车道差和可用路长选择过渡长度。单端最多使用该道路 80% 的长度，两端同时需要过渡时各最多使用 42%，保留中间断面。
- 断开、删除或替换相邻道路后重新推导过渡。保存、重载和撤销后使用相同规则恢复。

车道宽度差大于 0.2 米的接口不自动处理；较小宽度差仍使用各资产的原始车道宽度，通过原有短连接衔接。过渡长度是原型参数，极短路段需要玩家延长。

## 实现接口

`src/core/auto-transitions.ts` 提供两个独立函数：

```ts
updateAutomaticTransitions(project: Project): void;
automaticTransitionPreview(project: Project, incoming: Road[]): {
  roads: Road[];
  replaces: string[];
  hasTransitions: boolean;
};
```

`updateAutomaticTransitions` 原地更新派生字段 `Road.autoTaper`，不会修改道路 ID、名义车道数、控制点、车道转向规则、车道接口或路网通行口。端点候选使用空间单元筛选；重复运行得到相同结果。

`automaticTransitionPreview` 对道路副本计算预览，返回新增及受影响的道路，以及需替代显示的原道路 ID。原地图和输入道路不被修改。编辑器的预览和正式提交应调用相同的派生规则。

派生字段包含起点／终点的有效车道数、保留车道组起始索引、横向偏移和局部曲线参数范围。`src/core/math.ts` 中 `baseCountAt` 读取名义断面，`countAt`、`laneWidth`、`lanePoint`、`boundaryPoint` 和 `center` 读取有效断面。路面与模拟无需各自实现另一套过渡逻辑。

导入时校验派生字段；道路编辑及模拟 configure 时重新生成。普通道路内部自动分段后，先清除复制的派生字段，再依据实际相邻路段重新推导；不要把一次自动过渡改写成显式 `lanesStart/lanesEnd` 渐变资产。

## 验证

`tests/auto-transitions.test.ts` 覆盖普通 2→3、3→2、不同保留车道组、双向道路、双端短路段、断开恢复、路口／分流排除、存档、连续路面边缘、预览不修改地图，以及真实车流通过而不发生车身重叠。

`tests/browser/auto-transitions.spec.ts` 使用普通道路资产和真实鼠标验证建造、自动过渡预览、保存重载、删除恢复、撤销、双向道路和窄屏布局。

自动过渡不改动红绿灯、局部预测让行或其他驾驶策略。
