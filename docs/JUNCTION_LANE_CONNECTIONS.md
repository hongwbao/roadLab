# 路口车道连线

按 J，或点击“车道连线”工具，再点击两条道路相连的接头或路口中心。普通直连、转角、自动分段、车道数变化、双向与非对称道路，以及偏移分流／汇流都可编辑。
地图会显示路口轮廓、青色通行曲线、实心入车道圆点和空心出车道圆点。

- 从实心入车道圆点按住拖到空心出车道圆点，松开添加连接；也可依次点击入车道和出车道。再次点击已连接的出车道，移除连接。
- 拖动已有连线保持该出口开放；拖到空白或非法目标不改地图。仅从入车道圆点开始的拖动占用鼠标，其他位置仍可操作镜头。
- 同一入车道可连接多个出车道，包含原自动规则未分配的目标车道。
- 点击一条曲线可选中它，按 Delete 或面板按钮删除；右键曲线也可直接删除。
- “禁止全部出口”明确关闭选中的入车道。“此车道恢复自动”和“整个路口恢复自动”撤销相应自定义规则。
- 右键空白取消当前选择。J 或 Esc 退出工具。折叠的“按名称选择车道”提供键盘按钮操作。

所有规则作用于实际寻路和驾驶网络。编辑会重置交通测试，并随地图自动保存，支持撤销、重做和 JSON 地图导入导出。

## 数据与生成

`Project` 和 `Blueprint` 的可选 `junctionLaneConnections` 存储每个源进口车道的完整目标列表：

```ts
type JunctionLaneEndpoint = { road: string; lane: number; end: 0 | 1 };
type JunctionLaneRule = {
  from: JunctionLaneEndpoint;
  to: JunctionLaneEndpoint[];
};
```

没有规则时使用原自动连接；`to: []` 是明确禁行，不能当成缺省配置。
只有配置过的源车道被替换，其余车道继续使用自动连接。自定义连接优先于原来的粗粒度转向限制。
旧地图没有此属性，连接行为不变；退役的 `Project.connections` 字段仍不使用。

核心模块枚举同一路口的全部合法入/出车道对，而不是仅过滤原自动结果。
不能跨层连接、连接另一处路口、连接入车道作为出口，或连接同一道路掉头。普通物理交叉路口保留原吸附限制；偏移连接路口内，吸附决定道路位置，自定义连线可以覆盖原吸附车道对应关系。
拆分道路时，原终点的引用迁移到后段 ID，新产生的接头同样可编辑。双向道路反向时，端点与车道索引同步反转，保留原物理车道的映射和禁行；单向道路反向会使原进出方向失效，清理相关源和目标。道路侧边增减车道沿用物理车道索引重映射；道路拆除、车道消失或接头移开后会清理失效引用。
保留有效源车道的空目标列表可以避免删除某个出口后重新开放其他方向。
复制和模板只携带所有引用道路均被复制的完整规则，并重映射道路 ID。

`applyJunctionLaneRules` 在没有自定义数据时直接返回原自动数组，避免额外扫描路口。
`junctionLaneLayout` 的物理路口与偏移节点使用实际路口 trim 和有灯时的停止线偏移；曲线采用两端切线和 0.45 倍端点距离的控制柄。普通连续接头为了让重合的进出圆点可选择，沿真实道路设置编辑用内缩端口，辅助曲线显示同一份实际连接关系。这个内缩不改变实际道路 trim、车辆停车规则或交叉路口分类。

## 偏移连接路口

`buildLaneJunctions` 将同位置端点、有效的车道吸附关系，以及旧地图中同层同向、车道中心实际接触的端点归成同一连接组；不会因为道路平行或桥上下重合而合并。接头两侧的主路延续段也会加入该组。节点至少包含两条不同道路；孤立道路的首尾即使重合，也不虚构可编辑连接。

普通未铺面接头标记为 `kind: "continuation"`，偏移连接组标记为 `kind: "attachment"`，真实铺面路口保留原分类；两岔转角也能编辑。`isLaneJunctionEditable` 统一工具和统计入口。物理铺面独立使用原 `buildJunctions`；编辑端点遵循与真实连接相同的0.5m高度上限，物理铺面0.65m容差不会把不连通的层强制归为同一编辑节点。

无attachment的侧向错位端接，也按真实入／出车道恢复：车道中心使用实际连接的 `max(width) * 0.7` 近接半径，同时要求同向切线、两端纵向误差均不超过0.65m，且端截面横向有重叠。1m横移，或0.49m高度差叠加0.8m横移，都能编辑；整段邻近平行、纵向留缝、逆向或不同层不会据此合并。新恢复接头仍是continuation；识别只依赖道路端接，全部出口禁用后节点仍可选择、恢复和重连。

操作仍是按J、点击接头，再拖动或点击实心入车道和空心出车道。面板区分“道路接头”“转角路口”和“偏移连接路口”；逻辑节点的车道名称包含进口／出口编号、道路名和车道号，避免并行出口重名。并行分支的圆点沿各自真实车道错开放置，方便点击；“按名称选择车道”仍可操作。地图统计为“连接节点”，包含普通分段和偏移组。当前120段苜蓿叶示例共有104处可编辑节点：24处偏移连接组与80处普通连续接头，物理交叉路口仍为0。

偏移连线使用原有`junctionLaneConnections`保存，不需要迁移存档。添加或删线、禁行、恢复自动、撤销、重做和地图JSON都适用。未设置规则时，原自动车流连接与道路几何保持原样。配置过的偏移节点会为车辆连接曲线提供接头前后的行驶长度，使用两端道路切线平滑接入；不把车瞬间横移到相邻车道。

扩展车道连线节点不额外铺设街道路口面、斑马线或自动信号灯；原分流铺面裁切和高架分层继续使用自身几何。`laneJunctionTrims` 仍仅为已经配置规则的attachment节点增加实际连接跨度；普通continuation内缩只用于编辑显示。有灯路口的停止线偏移仍计入车辆连接曲线。

## 平滑接头的完整车道权限

3车道接4车道时，自动平滑领口会在接缝处把新增车道的实际宽度暂时收为0。这是几何渐变，不代表四车道道路丢失了一条车道。J工具现在按去掉派生 `autoTaper` 后的原端点车道资格显示3入4出；4→3则显示4入3出。道路原本的 `profile` 和驶入／驶出方向仍参与判断，不能借此给真正终止的车道或逆行车道生成假端口。

`src/core/junction-lane-geometry.ts` 的 `isJunctionLane` 用于逻辑资格，`physicalLaneEndpointT(road, lane, end, minimumWidthRatio)` 则沿已有车道曲线，从原端向内求首次达到实际可行驶宽度的位置。圆点位于真实车道曲线上；车道名称仍按原道路的同向车道编号。交通消费使用同一阈值与真实已编译片段接入显式连线，不修改默认自动连接或为普通接头统一添加trim。

开关平滑、撤销／重做和保存重载不会把原有第四目标清成空列表。显式 `to: []` 仍表示禁止通行。旧版本若已经将某条连线保存为空，无法与用户主动禁行可靠区分，因此不会猜测并自动重开；需要用户重新连线，或使用含原规则的历史／存档。

`tests/smooth-join-lane-ports.test.ts` 与 `tests/browser/smooth-join-lane-ports.spec.ts` 覆盖3→4、4→3、2→3、非对称双向隔离带、真实第四目标、平滑开关、禁行、历史和重载；交通网络与实车检查使用同一冻结源中的消费适配。
