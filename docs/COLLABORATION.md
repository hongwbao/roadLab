# 同一项目中的多会话协作

所有功能最终集成到 `/home/bhw/repos/interchange-lab`，使用同一个道路模型和同一份已验证的网站版本。按文件归属并行开发，而不是让多个会话同时改同一个入口。

## 当前分工

运行中的确切归属、测试端口与交接状态保存在 `.coordination/owners.json`。它属于本机协调信息，不提交到公共仓库。

## 共享入口的交接

1. 功能会话完成独立模块和测试，不直接编辑已经归属别人的文件。
2. 将共享入口所需改动作为最小补丁，连同接口约定写到 `.coordination/handoffs/`；不要打包整个脏工作区。
3. 集成会话确认文件暂时没有其他写入者，逐项接入补丁，处理接口冲突。
4. 先运行对应功能测试，再运行类型检查和全量回归，确认原有功能仍可使用。
5. 所有已交付功能一起构建、发布，避免后一项功能的旧基线覆盖前一项功能。

临时 worktree 可以用于验证补丁，但不作为另一个独立产品发布。会话不能自行接管别人的共享文件；交接通过文件登记和明确的会话消息完成，不依赖“最近看起来没人改”。

## Git、测试与发布

Git 暂存和提交使用本机文件锁，例如 `flock .coordination/git.lock git commit ...`；只暂存本轮明确交付的文件。锁只保护 Git 写操作，不能代替源码文件归属。

红绿灯、自动过渡、自动分段分别使用 5175、5176、5174 测试端口。日志分别写在 `.cache/signals/`、`.cache/auto-transitions/`、`.cache/road-segments/`。构建输出使用 `.cache/builds/<feature>/dist`；生产服务器始终服务已经验证的固定快照。

协议本身不会强制阻止任意进程改文件。每个参与会话都必须读取并确认归属；已经在运行的会话需要显式接收通知，不能只依赖新建 AGENTS.md 自动生效。
