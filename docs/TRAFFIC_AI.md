# 交通 AI：第一版道路车辆模型

这一版以“建造立交、修改路网后，能看到车道使用和拥堵变化”为目标。参考《都市：天际线 2》公开介绍的行为方向，独立实现道路车辆的跟车、选道、汇流、路口通行和拥堵绕行。没有使用或取得该游戏的完整交通源代码，也不声称算法及参数与原作相同。

## 已实现行为

| 行为         | 实现与可观察结果                                                                                                                              |
| ------------ | --------------------------------------------------------------------------------------------------------------------------------------------- |
| 跟车与起停   | IDM 模型根据自身速度、前车速度、净车距和期望时距计算加减速。高速接近慢车时提前减速，排队时保持停车间距，队列释放后逐辆起步。                  |
| 驾驶差异     | 每辆车具有确定性的期望速度、时距、加速度、舒适制动和礼让程度。重置相同地图后可重放，司机差异不会消耗需求生成器的随机数。                      |
| 超车与回归   | MOBIL 思路比较换道前后的加速度收益，并计入新旧车道后车的影响。高速道路空闲时有靠右倾向；变道完成后至少等待 2.5 秒再自主变道。                 |
| 出口预选道   | 根据路线提前靠向出口，只进行相邻车道变换。短路段按剩余变道次数分配距离；低速等候时可缩短变道距离。                                            |
| 车道收窄     | 根据沿线实际车道宽度估计可用距离，提前寻找并道间隙；禁止为超车驶入来不及返回的消失车道。                                                      |
| 汇流         | 多个进口进入同一出口车道时共享通行预约。自由流时主线优先，两侧都形成队列时倾向交替放行，长时间等候会提高优先级。                              |
| 无信号路口   | 仅根据出口目标车道是否有容纳整车的空间决定能否进入；不检查横向车流，不按转向路径分配路权。正常跟车和车身防穿模独立保留。                      |
| 防止堵住路口 | 目标出口没有容纳整车的空间时，在路口外等候；空间释放后重新申请。                                                                              |
| 平滑转向     | 沿弧长参数化 Bézier 曲线转向，根据曲率限制转弯速度；跨越路段与路口曲线时保留积分余量，避免边界顿挫。                                          |
| 拥堵绕行     | 路径成本综合自由流时间、车道变换、转向、横向衔接和队列延误。延误每秒采样并平滑；当前路段或前方路线拥堵时评估绕行。                            |
| 稳定选路     | 新路线至少节省 2.5 秒且优于旧路线 15% 才采纳；成功改道后冷却 10 秒，未改道的重评估间隔至少 5 秒。错过可完成的变道位置时允许尝试可行替代路线。 |
| 车身保护     | 每次积分使用车道占用快照，变道车同时占用起止车道。保留空间索引和有向车身矩形检测作为最后保护，不能通过删除排队车辆消除拥堵。                  |

当前无信号路口采用用户确定的阶段规则：只按出口空间准入，不做横向让行；后续再用红绿灯控制路权。400% 需求允许明显拥堵，包括交叉车流在车身保护作用下形成的僵持，不通过降低流量或移除车辆保证通行。无信号路口的出口容量检查与驾驶预判使用同一段 80 米范围，不因尚未进入近距离判定范围而提前制动；队首资格仅用于虚拟汇流预约，普通直行按正常跟车连续通过斑马线。虚拟汇流点仍保留共享目标车道的预约。交替汇流只有在两个接近进口均排队并且出口可容纳车辆时参与决策，不能为消失车道强制创造物理空间。

## 代码与调参

- `src/simulation/driving.ts`：IDM、换道收益、安全制动、驾驶员参数和停车积分。
- `src/simulation/lane-traffic.ts`：按道路、方向、车道和连接曲线分组的不可变占用快照，查询前后车辆。
- `src/simulation/intersections.ts`：虚拟汇流点的共享目标车道预约、等待老化、主线优先和排队汇流；无信号交叉路口不进入该仲裁器。
- `src/simulation/simulation.ts`：车道级寻路、发车、交通采样、变道轨迹、连接曲线和模型调度。
- `src/simulation/collision.ts`：车身碰撞检测和空间索引。

内部使用米、秒及米/秒，地图道路限速仍以 km/h 保存。默认驾驶参数为期望时距 1.25 秒、停车净距 1.7 米、加速度 2.4 m/s²、舒适制动 2.5 m/s²、紧急制动 8 m/s²；司机个体参数在附近浮动。换道安全条件要求目标后车的预计制动不超过 4 m/s²。路口转弯速度使用约 2.3 m/s² 的横向加速度估计；汇流预约使用的路径宽度阈值为 2.5 米，不用于无信号交叉路口的入场检查。

需求仍使用已有的 0–400% 车流滑块及每个入口的流量。时间倍率独立于车流量；道路编辑会重新配置模拟，只调整车流量会保留车辆和统计。

开发时可通过 `window.lab.editor.simulation.statistics` 查看换道、改道、路口入场和保护性停车计数。`safetyStops` 是碰撞检测拒绝一次运动的次数，不是已发生的车身重叠数；并发计数按同一个路口统计。统计只服务于开发，不增加编辑器选项面板。

## 验证

```bash
npm run check
PLAYWRIGHT_PORT=5174 npm run test:e2e
SMOKE_URL=http://localhost:5173/ npm run test:smoke
```

`tests/traffic-ai.test.ts` 覆盖接近速度制动、排队起停、停车积分、驾驶差异、换道礼让与安全、超车回右、连续相邻变道、兼容路径并行、真实路口出口阻塞、队首通行、汇流公平性、拥堵改道冷却及确定性重放。

`tests/unsignalized-junction.test.ts` 验证横向车辆在出口可用时入场、六条对向直行车道并行、四个独立右转并行、同一连接曲线连续跟车、出口堵塞等待、空路口直行无额外减速、路段和连接曲线边界的行驶距离连续性（含零长度及短连接），以及选道和可用变道距离。

原有 `tests/traffic.test.ts` 持续模拟拓宽分流、十字路口和收窄汇流各 360 秒，逐帧检查车身重叠、位移和转向。拓宽分流及汇流继续要求持续通行；400% 无信号十字路口允许拥堵，验证有车辆进入、形成排队且不穿模，不再要求每分钟必须通过最低车数。`tests/shared-map.test.ts` 对用户的 18 段共享地图运行 400% 需求共 240 秒，检查每分钟持续通行和所有出口进展。运行统计输出到忽略提交的 `artifacts/`。

## 范围与后续

当前只有同尺寸小汽车及无信号路口。尚未实现交通灯相位、公交与行人、停车与寻位、服务车辆、紧急车辆、事故、交通法规设置和市民出行成本。没有用真实道路数据校准；复杂短路段、极端急弯或几何空间不足的路网仍可能拥堵，需要通过道路设计解决。车辆上限仍为 350，需求超限时在入口外排队。

## 设计依据

- [CS2 官方 Traffic AI 介绍](https://www.paradoxinteractive.com/games/cities-skylines-ii/features/traffic-ai)：公开行为方向，如路径成本、车道使用和路线调整；不是算法源码。
- [IDM 原作者说明](https://traffic-simulation.de/info/info_IDM.html)：本项目跟车模型的公式来源。
- [MOBIL 原作者说明](https://traffic-simulation.de/info/info_MOBIL.html)：本项目换道收益、礼让与目标后车安全条件的依据。

IDM、MOBIL 是本项目自主选择的模型，不代表 CS2 使用这些模型。无信号路口准入、汇流策略和调参为本项目实现。详细寻路流程及扩展规模的方案见 [寻路与性能](PATHFINDING.md)。
