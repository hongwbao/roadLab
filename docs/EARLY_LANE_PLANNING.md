# 固定道路路线与实时车道预判

RoadLab 在宿主策略层实现这套行为，接入实际 source runtime；底层导航、车辆运动和碰撞保护继续使用原有模块。这是按本项目需求实现的策略，不代表已完整复刻《都市：天际线 II》的交通系统。

## 道路路线与车道分工

车辆出发前完成全局寻路，固定道路及连接序列。车道不随这次寻路锁定：行驶时依据实际连接、路口自定义连线以及周围车辆实时选择。原运行链请求修复路径缓冲时，从最初路线的当前位置恢复剩余序列，不重新选择另一组道路。

默认预判距离为 **500 米**。从“地图菜单 → 交通 AI 设置 → 车道预判距离”可调整为 **100–2000 米**。参数随地图保存；旧地图缺省为500米。运行中修改保留车辆、时间和统计，下一模拟帧更新预判缓存，不重新编译路网或重建路面。

## 预判与执行

1. 从当前位置沿既定路线计算移动窗口，包含道路拟合片段、连接和后续道路。窗口随车辆行驶前移，不能把刚进入长道路时的结果缓存到整段道路结束。
2. 使用实际编译路网的后继关系，倒推哪些当前车道可抵达路线中的后续连接。自动连接与自定义连线采用相同检查；未来普通车道组允许相邻变道，路口连接内禁止横向变道。以剩余所需变道次数选择合适车道。
3. 当限制进入窗口，立即开始准备。每次只移向相邻同向车道，完成后再进行下一次，不直接跨越两三条车道。普通超车也受相邻车道、安全间距及路口前距离约束。
4. 前方空隙至少6米或1.1秒车距，后方至少6米或后车1.3秒车距。开始变道前沿连续物理车道检查前后车辆，跨拟合片段与普通分段接头，不能把当前小段为空当成有安全间隙。
5. 普通择道等待现有安全空隙，不主动压低本车或邻车速度来挤出空隙。必需转向的多车准备仍按到达限制位置的预计时间及稳定车辆编号协调，保留真实车辆之间的必要让行；同一目标空隙只允许一个请求。同侧已开始的变道受保护，对向请求按优先顺序错开。
6. 下一段连接必须是当前实际车道的合法后继，不能借队列跳到不相连的出口。未完成横向移动时不能直接进入真实路口连接。对普通道路分段接头，仅在同向车道等数、全部合法后继逐一对应、车道中心/宽度/切线连续且没有分合流时，允许沿原有两条相邻车道继续完成换道；自定义禁止、交叉连线、车道增减、隔离带/横向偏移和真实路口仍保留原边界检查。
7. 跨普通接头继续换道还要检查接头后两条延续车道的前后安全间距，使用连续纵向坐标，防止把下一条道路开头的慢车漏掉。前方目标车道没有安全空隙时仍减速等待；这不是让车辆直接跳过连接或无条件放行。

选择车道、开始或正在横移都不附加限速。旧的25–60米变道准备制动策略已经移除；无前车、无红灯的直路可以按原巡航速度完成相邻变道。真实前车、信号灯、限速变化、弯曲道路及实际车身安全仍约束速度；未完成合法车道准备时，真实路口的连接边界仍不能越过，持续超饱和路网也仍可排队。

## 按前方车数实时择道

先遵守固定道路路线、500米内的转向准备和自定义连线，再比较所有合格同向车道的前方实际车辆数，选择数量最少的最终目标。目标可以相隔多条车道，执行时逐条相邻移动。空但不满足既定路线的车道不参与比较。

计数窗口与预判距离共用设置，默认前方500米；沿同一物理车道跨拟合片段及连续、完整合法双射的普通分段接头累计，在真实分合流、交叉或不连续连接处截断。排除自身、对向和后方车辆，同一车身跨片段只计一次。导航目标可能先进入下一段，计数仍使用真实车身纵向位置，并保留接头附近的前后片段，避免出现虚假的空道。

通常每秒重评一次；进入新路径组、合法候选变化或实时修改预判距离时即时更新。平局优先保持当前车道，其次保持仍然最优的既有目标；已经开始的相邻横移先完成，再决定下一步。普通择道在真实路口附近暂缓新的横移，连续普通接头不受此限制；必需转向准备不受普通复评计时延误。

## 性能与验证边界

车道可达性按车辆当前路径组、组索引及移动窗口终点缓存；只有窗口跨过新片段、车辆换组或参数变化时重算。普通接头的连续性和计数走廊按编译路网缓存，修改连线并重新配置时清除。车辆计数复用运行时已排序的物理车道占用，以二分定位窗口，只遍历窗口内记录并去重。局部空隙协调继续使用同一步快照，不为每辆车每帧执行全路网寻路或扫描全网车辆。

自动化验证包含：移动窗口跨多条道路和连接的倒推、自动和自定义专用右转、相邻连续变道、四辆并排行驶的让出空隙、实际显示车身不重叠、固定路线的路径缓冲修复，以及运行中参数调整和存档恢复。测试场景通过不等于所有道路规模或拥堵形态已经解决；持续高压下既有的独立碰撞回归仍保留原断言与失败记录。

## 普通分段接头修复（2026-11-08，独立交付）

已复现额外减速，尚未复现死锁：同一条480米直路，拆成4段120米后，单车距第一接头10米开始换道、初速100km/h，旧边界截断令最低速度降到1.61m/s。允许符合上述严格条件的连续换道后，接头速度保持约27.78m/s；未拆分对照也保持同等速度。此修复不改变底层车辆运动、信号灯或碰撞算法。

最新120段改进版苜蓿叶立交的单车诊断包括入口左/右车道到四个出口的8组组合，全部完成、无失败；需要在第一普通接头换道的6组，首接头最低约1.14m/s提高至约27.78m/s。完整行程仍存在真实分合流和出口附近的减速，不能据此声称全图不停车或拥堵/死锁全部解决。接头后3、10、30米分别放置0或10m/s慢车的6组验证继续要求车身重叠为零、两车全部完成；另覆盖后方快车和显式禁止/交叉连线、真实路口、断面变化及规则修改后的缓存失效。

本轮为有界交通回归和数据诊断，没有重跑全浏览器或400%压力场景，历史碰撞压力失败仍保留；未操作公共5173发布。

普通二度节点的自定义连线依赖道路建造模块新增的节点编辑与规则消费能力。交通模块只依据编译后的真实合法后继识别连续性，不自行补造连线；因此这部分禁行/交叉连线及规则修改回归必须随道路模块统一验证、发布。旧道路模块不能将这三项集成场景视为已支持。
