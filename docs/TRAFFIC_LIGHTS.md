# 红绿灯

红绿灯是可选的路口控制功能。新添加的灯默认采用提供的天际线 2 程序集所对应的自动感应逻辑；原有两种手工配时模式继续可选。计时、车辆决策、地图操作和渲染放在独立模块中。

## 操作

点击左侧红绿灯工具或按 K，选择三岔及以上路口的中心，再点击“添加红绿灯”。右侧浮层显示当前通行组和绿／黄／全红状态。自动模式显示“感应控制”，手工模式显示剩余模拟时间。停止线位于斑马线前。

可选三种配相：

- **自动感应（默认）**：按实际连接生成信号组，根据车辆请求选择、延长和切换通行组。普通十字路口的对向车辆同组，包含转向；左转车辆通过车道冲突与让行逻辑处理。地图显示普通灯头，面板隐藏手工配时滑块。
- **直行／左转分相**：将近似对向的进口分组，直行与右转同时放行，左转使用独立相位。默认通行绿灯 20 秒、左转 8 秒。
- **逐进口轮放**：每次允许一个进口的所有可用转向，适合共用转向车道较多的路口。

手工模式区分左转与直行／右转灯头，只生成实际可达的车流方向。修改车道转向规则或连接后重新生成相位。红灯右转、行人相位和手工逐车道相位编排尚未实现。

手工模式下，“黄灯、清空与协调”可调整黄灯、全红最短时间和启动偏移，默认黄灯 3 秒、全红 2 秒。自动模式使用独立的七态时钟、源请求优先级与扩展规则，不把这两项手工数值当作源配时。所有计时使用模拟时间，暂停会停表，1×／2×／4×同步生效。修改设置会重置交通测试。

点击“移除红绿灯”或在此工具中右键点击路口，可恢复无灯控制。添加、修改和移除均支持撤销重做，配置随地图保存。K 或 Esc 退出工具。

## 行车规则

默认交通内核将信号的 Stop、SafeStop、Yield、Go 状态传给完整车道速度迭代器，同时处理下游空间、跟车、重叠窗和预约。无灯路口也采用这条源决策链。旧 IDM/MOBIL、5 秒预测和独立准入回滚属于内部 `legacy` 对照路径，不参与新内核。

红灯与安全黄灯的制动依据源速度迭代器、实际物理位置、车身尺寸及车道曲线。前视路径最多 12 条车道，按车辆行进补充；它不是固定米数的整体路口锁。

自动模式的原始信号分组、七态转换、车道信号与灯头计算分别见 `CS2_SIGNAL_GROUPS.md`、`CS2_SIGNAL_CLOCK.md`、`CS2_RECONSTRUCTION.md`。直接执行原 DLL 的数值对照、提取原方法体的容器适配和浏览器组合回归是不同证据，不能互相替代。

手工配时模式继续按绿灯、黄灯和全红循环，并可在路口仍有车辆时延长清空。这是 RoadLab 的配时扩展，不宣称是原版自动时钟的配置界面。内部 legacy 对照还保留原准入记录与碰撞回滚机制，相关实现专用测试明确标注模型。

正常等红灯不会仅因停车时长而触发源 Stuck；源阻塞依赖链、空间请求和路径失败另由路径策略处理，失败行程与正常完成分开计数。

## 模块边界

| 文件                               | 负责内容                                           |
| ---------------------------------- | -------------------------------------------------- |
| `src/core/traffic-signals.ts`      | 保存的数据结构、默认配置、路口绑定、导入校验及复制 |
| `src/simulation/traffic-lights.ts` | 配相、模拟时钟、黄灯决策、全红清空与灯态查询       |
| `src/editor/traffic-light-tool.ts` | 路口选取、添加移除及配时修改事务                   |
| `src/render/traffic-lights.ts`     | 灯杆、左转与普通灯头、停止线和灯态更新             |
| `src/ui/traffic-light-panel.ts`    | 配时浮层、当前状态和相位列表                       |
| `src/simulation/cs2-simulation.ts` | 车辆请求、车道信号输入与源普通车速度/预约循环      |
| `src/simulation/cs2-junctions.ts`  | 源七态时钟、组选择和车道/灯头投影                  |
| `src/simulation/simulation.ts`     | 应用入口与 legacy 对照模型                         |

`Project.signals` 是可选字段，旧存档默认没有红绿灯。配置绑定道路端点组合，内部自动分段会迁移绑定，整体移动时更新位置。完整路口复制和模板放置会复制配置并重建引用；不完整选择不复制信号配置，避免悬空引用。路口拆除或不再构成三岔路口时清理失效信号。

## 验证与边界

`tests/traffic-lights.test.ts` 覆盖手工时钟、源普通车实际信号输入、出口阻塞、对向并行、多周期车身分离、高速制动、复制与保存；原准入回滚等测试明确使用 legacy。源自动时钟、分组和完整车道迭代器由各自独立 oracle 测试覆盖。

`tests/browser/traffic-lights.spec.ts` 验证默认自动模式与两组显示、隐藏手工滑块、保存重载、切换手工模式、配时、移除与撤销、模拟暂停倍率，以及桌面和窄屏操作。

信号灯不能消除超出道路容量的拥堵。最终源引擎仍需复杂路网、长期高压、原车型资源与其他交通参与者的组合验证；没有完整原游戏运行时的对照轨迹。当前线上版本和开发中的功能状态以 `CS2_RECONSTRUCTION.md` 为准。
