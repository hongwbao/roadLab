# 红绿灯

红绿灯可按路口开启或移除。新增十字路口默认采用可编辑的四相位方案；自动感应、直行／左转分相及逐进口轮放继续可选，旧存档保留原模式。

## 默认十字路口与自定义相位

点击左侧红绿灯工具或按 K，选择路口中心，再点击“添加红绿灯”。十字路口默认按以下顺序循环：

| 相位 | 通行方向                     | 默认绿灯 |
| ---- | ---------------------------- | -------- |
| 1    | 东西直行，以及四个进口的右转 | 20 秒    |
| 2    | 东西左转，以及四个进口的右转 | 8 秒     |
| 3    | 南北直行，以及四个进口的右转 | 20 秒    |
| 4    | 南北左转，以及四个进口的右转 | 8 秒     |

进口名称使用地图方位，北对应 -Z、东对应 +X。略有倾斜的十字路口采用唯一的方位匹配，不把两个进口重叠到同一个方向。

在“自定义相位”中点击某个相位，可改名称和绿灯时间，并在矩阵中逐进口勾选直行、左转、右转。支持 1–16 个相位，每相位 1–180 秒；可以新增、删除、上移、下移及恢复默认。允许创建不放行任何方向的等待相位；该相位所有方向保持红灯，不会被静默删除。运行中的相位与正在编辑的相位分别标记。

相邻相位都放行的同一车道通行连接持续保持绿灯，包括最后一相位回到第一相位。默认四相位均勾选四方向右转，因此右转在整个循环中保持绿灯；未勾选的右转仍按所处相位受控。只有本相位放行、下一相位不再放行的方向进入黄灯与清空；新放行的方向等必要过渡结束后才变绿。默认黄灯 3 秒、清空最短 2 秒，可在“黄灯、清空与协调”调整，并可设置启动偏移。

单相位或相邻两相位的实际通行集合完全相同时，直接衔接各自绿灯时长，不插入黄灯与清空间隔；总周期和启动偏移按实际时间计算。允许继续绿灯的车辆不会单独导致清空无限延长，其余未驶离车身仍保留清空保护。面板在部分方向持续绿灯时显示“换相黄灯”或“换相清空”，并注明“部分方向保持绿灯”；地图上的各方向灯色和车辆放行使用同一规则。

所有计时使用模拟时间，暂停停表，测试倍率同步生效。修改路口相位或配时会重置当前测试，并支持撤销重做；存档和模板格式不变。

停止线位于斑马线前。地图显示左转、直行、右转三个独立箭头灯头；灯色按实际“进口 + 转向”连接计算，不能把“东西左转 + 四向右转”误显示为南北左转也放行。

## 保存、导入和备份方案

展开“方案保存与导入”，填写名称，点击“保存到本机”。同名方案替换旧版本，本机最多保存 24 个方案。选择另一个路口，在下拉列表选择方案，再点击“导入当前路口”。

方案按进口方位／朝向和转向存储，不包含原道路 ID，因此可以在道路 ID 不同的路口使用。缺失进口不放行；新出现的进口不会自动获得通行许可，需要在矩阵中勾选。方案里的每相位名称、时间、转向，以及黄灯、全红和启动偏移一并导入。

“导出 JSON”把当前方案下载为文件，“从 JSON 文件导入”可跨浏览器或设备恢复。空文件、无效 JSON、错误版本、重复相位／方向、无效转向和超限数据会显示错误，并保留当前路口配置。文件上限为 500 KB。本机方案库损坏时不会自动覆盖，可显式清空损坏记录后重新保存；浏览器无法保存时可以导出文件备份。

路口正在使用的方案随地图保存、自动保存、复制和模板放置。命名方案库单独保存在当前浏览器的本机存储；导出的 JSON 文件用于跨浏览器备份。删除本机方案不移除已配置在路口上的方案。

## 其他模式与行车规则

- **自动感应**：沿用提供的天际线 2 程序集对应的信号分组、七态时钟、来车请求及扩展规则。面板显示“感应控制”，手工绿灯／黄灯数值不替换原式配时。新增非四岔路口仍沿用该默认模式。
- **直行／左转分相**：近似对向进口成组，直行和右转一相位，左转独立相位。
- **逐进口轮放**：每次允许一个进口的所有可用转向。

真实默认交通内核从同一个 `TrafficLightController` 获取 Stop、SafeStop、Yield、Go 车道信号，继续处理跟车、下游空间、重叠窗和预约。自定义相位是 RoadLab 的手工配时扩展，不宣称是原版自动时钟的配置界面。配置只指定可通行连接，不替代路网的车道转向规则和车辆冲突处理。

自动分组使用独立的 `sourceStraight` 元数据保留原式直行判断；界面方向和手工相位按 RoadLab 地图方向解释。自动感应继续使用原式七态时钟和按信号组保留绿灯的规则，本次不改其状态机。固定配时模式的黄灯与清空按实际车道通行连接判断，非持续绿的车辆尚未清空时可延长清空阶段。正常等红灯不会仅因停车时间而被计为路径失败。

点击“移除红绿灯”或在红绿灯工具中右键点击路口，恢复无灯控制。K 或 Esc 返回地图工具。信号不能消除超出道路容量的拥堵。

### 车辆占用接口

`TrafficLightController.update(dt, occupiedJunctions, occupiedMovements?)` 的可选第三参数为 `ReadonlyMap<junctionId, ReadonlySet<movementId>>`，记录实际车身占用的通行连接，直到车尾驶离，包括车头已经进入出口车道的情况。控制器在实际到达的相位边界计算前后相位交集，只有持续绿的占用不会阻挡清空；其他连接、旧相位残留和未知连接都保守保留保护。某路口缺少逐连接记录时，回退原有整路口占用检查；不传第三参数的调用行为保持兼容。

`SignalState.continuousMovements` 给出过渡中实际保持绿灯的连接，用于面板说明；`stage` 仍沿用 `green`、`yellow`、`all-red`，后两者描述切换中方向的阶段，不代表所有方向灯色相同。单个方向的真实灯色与通行应查询 `armColor`、`laneSignal`、`allows`。

`tests/browser/traffic-lights.spec.ts` 覆盖默认相位和三个灯头、编辑／排序／新增／删除／撤销、跨路口方案与 JSON 文件恢复、保存重载、旧模式、窄屏控件及模拟暂停倍率。2026-11-07 已随车道连线整合部署，固定构建的 127 项相关测试和 50 项完整浏览器回归通过。保留的旧 protected 压力测试仍会检出车辆重叠，未计入通过结果；实际发布版本和范围见 [验证记录](verification.json)。
